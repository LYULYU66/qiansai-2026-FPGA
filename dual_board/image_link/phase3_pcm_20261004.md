# 双板第三阶段：低缓存开销的网络 PCM 接入

2026-10-04：源码接入、9 项 ModelSim 回归及两板完整顶层综合已完成。尚未布局布线、生成正式播放器 bit 或进行网线/HDMI 上板验证。原单板源码、`best_result/` 中的 bit、旧网口测试 bit 没有改动。

## 当前真实分工

B：唯一 TF 卡 → 原 FAT32/BMP/缩放模块与 PCM 读取 → 跨时钟小 FIFO → IMG2/AUD2 → 共用原 UDP/MAC → 网口。

A：IMG2 → 原 SDRAM 图片缓存/转场/HDMI；AUD2 → 原 512 字音频 FIFO → 原 48 kHz I2S/HDMI 音频链路。亮度、对比度、串口、报警、画面叠加等仍在 A。正常音频等待真正 PCM 数据，不输出测试音；欠载时输出静音，重新预缓冲后继续。

本阶段**没有完成频谱、波形、歌词时间轴和首页绘制向 B 的迁移**。这些目前仍在 A 计算/绘制，不能把本阶段资源当成最终双板分摊结果。

## 节约资源的做法

- 图片、音频共用一个既有 UDP 核和 PHY，不增加网口核、PLL 或 DSP。
- 每个音频包只保留一扇区：128 个立体声样本、512 字节 PCM。缓存为 512×8 位字节 RAM，TD 综合确认 A 接收/B 重传缓存各只用 1 块 BRAM9K；相比最初的双 16 位 RAM 各省 1 块。
- A 复用原 512×32 位播放 FIFO；B 同样复用原 FIFO 结构作为 100→125 MHz 桥接。没有保存整首音乐，也没有扩大原 SDRAM/FIFO 深度。
- 重试计数器按实际范围裁剪位宽；序号为可回绕的 16 位，不引入通用处理器或整套网络软件栈。
- 音频在包边界优先，不打断图片包。主、副板都在包级锁定发送源，防止不同类型的数据交叉。
- 发送源局部中止时补完已声明的 UDP 长度，并构造必定错误的应用 CRC，让接收端丢弃；避免网口等待剩余字节而卡死。这部分保留必要的少量保护逻辑。

## AUD2 协议

同图片协议使用 UDP 端口 `0x5002`。A 根据 UDP 长度分流：782 字节为 IMG2，530 字节为 AUD2；接收器仍检查各自魔数、完整长度和 CRC，不能仅凭长度信任内容。

| 字节 | 内容 |
| --- | --- |
| 0–3 | ASCII `AUD2` |
| 4–7 | 32 位会话号，小端 |
| 8–9 | 16 位块序号，小端，循环回绕 |
| 10–11 | 保留字节，必须为 0 |
| 12–15 | MUSIC.PCM 的立体声样本总数，小端，文件字节数÷4 |
| 16–527 | 128 个样本：左低/左高/右低/右高，signed 16-bit stereo |
| 528–529 | 字节 0–527 的 CRC16/CCITT-FALSE，大端 |

TF 卡仍使用既有 48 kHz、16-bit、小端、双声道 `MUSIC.PCM`，输出 HDMI 时沿用原左移 8 位转为 24-bit 的方式。文件必须包含完整的 4 字节立体声样本。块可跨歌曲循环边界，不要求整首长度是 128 样本的倍数。

AAK2 确认为 16 字节：`AAK2`（4）、会话号（4 LE）、块序号（2 LE）、A 已实际取出的累计立体声样本数（4 LE）、CRC（2 BE）。累计样本包含歌曲循环，不在网络包到达时递增。

发送器保留当前块直到确认，默认 125000 个 UDP 时钟（1 ms）后重试。A 校验完整块才开始向播放 FIFO 输出，确认在 128 个样本全部写入后发出。重复块只重复确认，不重复播放；忙于排空时到来的重试不能覆盖正在读取的 RAM。新会话只允许从块 0 开始，较旧会话被拒绝；同一会话中的 16 位序号回绕不复位播放。

## 时钟、缓冲与同步

- B：SD 100 MHz → 512 字双时钟 FIFO → UDP 125 MHz。启动 SD 音频扇区前保留足够空间容纳 128 个样本。
- A：UDP 125 MHz → 原 512 字 FIFO → 12.288 MHz 音频主时钟 → 48 kHz 双声道。启动阈值从 128 改为 256 字，约 5.33 ms 预缓冲；保留写侧余量，接收器可在块内暂停。
- 512 字的理论容量约 10.67 ms；实际水位控制预留了空位。它用于短时抖动，不保证长时间断网不停顿。长中断时静音并暂停歌词/播放样本进度，数据恢复后继续，不能把断网时间算成已播放时间。
- A 的实际 `pcm_read && !empty` 驱动单调样本计数，以 Gray 编码双级同步到 UDP，并随确认回传。B 已接入反馈解析端口，尚未用它运行远程频谱/歌词算法；不能称为已完成全系统远程音画同步。
- 新会话清空 FIFO 后，额外等待同步释放复位，再输出第一个样本，避免丢首样本。

## 实际验证

ModelSim Starter 10.5b，最终整套回归于 2026-10-04 10:46:21 完成，9 项 PASS、零错误：

1. 原 IMGF 接收校验。
2. 原 1200 包、307200 像素整帧收发。
3. 100/125 MHz 像素 FIFO、暂停和指针回绕。
4. IMG2 整帧：数据损坏、确认丢失、写侧停顿、延迟 SDRAM 完成。
5. 可见图片保护、超时中止、不提交半帧。
6. 手动/自动切图、预警暂停。
7. AUD2：CRC/长度/文件参数错误、忙时重复包、乱序、16 位序号回绕、旧会话拒绝。
8. 发送源中途取消：补足 UDP 长度、必定错误的 CRC、另一通道后续正常发送。
9. 原生 FIFO＋原播放模块：100/125/12.288 MHz 时钟、48 kHz 取样；图片/音频并发仲裁；CRC 重试、确认丢失；14.4 ms 断流导致欠载后冻结进度并恢复；非整块歌曲循环；新会话重启。2048＋512 个 PCM 样本逐一核对，无重复/丢失。

原生 `rfifo_32_32_512` 在两个实例中合计产生 6 条未连接的 `doa/dib` 端口警告，属于原有单向 SDP RAM 的未用端口；没有隐藏这些警告，也没有修改单板 IP。新增模块和其它测试无警告。SD 顶层只完成连接展开，**未模拟真实 TF 卡文件系统、加密 UDP/MAC、PHY、完整 SDRAM/HDMI 或网线故障**。

重跑：在项目根目录执行 `& ./dual_board/image_link/sim/run_modelsim.ps1`。脚本不仅检查工具退出码，还要求所有 PASS 并拒绝任何 Fatal/非零错误，防止 ModelSim `$fatal` 后继续脚本造成误判。日志为 `sim/modelsim_regression.log`，音频波形为 `audio_media.wlf`、`audio_guard.wlf`、`media_abort.wlf`。
