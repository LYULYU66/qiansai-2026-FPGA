# 第九阶段：通信外围第一轮资源优化

只修改 `dual_board/image_link/`，不改单板源码、字模、约束、IP 和回退 bit。本阶段是一次可控的调度逻辑合并，**没有替换通用 UDP 栈，也没有删除 ARP 或 ICMP/Ping**。

## 优化内容

副板原有 information / graphics / media / link 四层二路仲裁，改为一个五路 `media_udp_scheduler`。主板原有 receipt / link 两层改为一个三路调度器。每块板分别只保留一套 owner、包长度、计数、启动等待与中止毒化 CRC 运算。

- B 优先级：链路握手 > PCM > 参数控制 > 可视化结果 > 图片。
- A 优先级：链路握手 > 实际播放进度确认 > 图片接收确认。
- 仅在空闲时锁定通道，锁定后即使尚未收到 UDP ACK，也不能被新来的高优先级请求抢走。已开始的包不拼接、不逐字节抢占。
- B 最大包 1042 字节，计数 11 位；A 只发送 10/12/18 字节包，计数 5 位。用剩余字节递减判断结束及 CRC 尾部，避免多套 16 位计数/减法。
- 媒体生产者局部复位时，调度器仍属于 base reset 域，继续完成已向 UDP 核声明的包长。缺失数据填零，尾部 CRC 故意反转一位，保证接收方拒绝这个包。没有删除已有 CRC、确认重传、会话世代、受保护缓存校验复用和独立复位恢复。
- 本地生产者非法长度不会被截断接受。接口仍要求 ACK 后连续出字节（允许最多七拍启动等待），没有引入不存在的逐字节背压。

原 `media_udp_arbiter` 保留作为历史测试参考，其模块内容未改变；正式 A/B 顶层已不再实例化它，因而不会保留六个旧仲裁器的硬件资源。三个生产文件的改动分别是 `media_udp_arbiter.v`（追加新模块）、`image_media_board_b.v` 和 `top_dual_image.v`。

## 最终候选：gate 综合

| 指标 | A 优化前 | A 本轮 | B 优化前 | B 本轮 |
| --- | ---: | ---: | ---: | ---: |
| LUT / 19600 | 15935（81.30%） | 15799（80.61%） | 13658（69.68%） | 13261（67.66%） |
| 寄存器 | 11522 | 11493 | 10005 | 9898 |
| BRAM9K / BRAM32K | 49 / 7 | 49 / 7 | 27 / 9 | 27 / 9 |
| DSP / PLL | 3 / 4 | 3 / 4 | 3 / 3 | 3 / 3 |

两板合计从 29593 降到 **29060 LUT，净省 533**；总寄存器减少 136，所有硬资源不变。相当于单块容量的总用量从 150.98% 降到 148.27%；相对两块总容量是 74.13%。这些只是资源口径说明，不能以两板平均值掩盖主板仍约 81%、PLL 4/4 的瓶颈，也不能将 gate 数字与单板布线后的 88.74% 混算。

还试过将毒化 CRC 的输入显式接到 payload，而不经过输出尾部选择器。虽然该表达式在 `remaining>2` 时与原式等价、调度器层级 LUT 略少，但整体 gate 变为 A=15848、B=13318，比最终候选合计多 106 LUT。因此没有采用。备份中的 `candidate_explicit_crc_*_gate.area` 仅为实验报告，不是最终版本。

## 仿真证据与范围

结果以 `phase9_validation_20261004.json` 校验后的固定日志为准。

原 30 项与新增四项组成的完整回归已运行；其中平坦调度测试使用过上述等价的显式 CRC 输入候选。选择低资源候选后，**又单独重新编译并复测最终候选的四项新测试**，不把另一候选的日志冒充最终调度器验证。

1. `tb_media_scheduler`：副板五路，31 个完整包；最大/最小包长、同时请求优先级、延迟 ACK、网口 ready 变化、锁定后高优先级到来和长度改变、首字节/中途/CRC 尾部中止、启动超时后源恢复、非法长度、base reset 后恢复。
2. `tb_media_scheduler_a`：主板三路，同类检查，23 个完整包。
3. `tb_audio_offload_flat`：实际 IMG4/AUD2/VIZ2/CTL2 收发器、原音频分析器、原生 PCM FIFO 和 48 kHz 播放头；CRC 重传、丢 ACK、断流冻结、会话重启、音量反馈和歌词样本计数。链路通道在这一 fixture 中未启用。
4. `tb_media_restart_flat`：实际 LNK1、五路/三路调度器、四缓存 ingress、PCM FIFO/播放器，连续五次 B 复位；受保护画面不被覆盖、四图预载和音频重启、播放头准确到最终 512 样本。控制和可视化通道在这一 fixture 中未启用。

第一版单元测试曾错误地以“ACK 时最高优先级”作为判据，导致失败；实际应以“请求被锁定时的最高优先级”为准。修正后两项单元测试通过。失败日志不计入通过证据；没有放宽正确的包锁定要求。

波形：`flat_scheduler_a.wlf`、`flat_scheduler_b.wlf`、`flat_audio_offload.wlf`、`flat_media_restart.wlf`。只跑新测试：`& ./dual_board/image_link/sim/run_modelsim.ps1 -Suite NetOpt`；默认完整回归包含 34 项。

这些测试不覆盖真实 TF/FAT/缩放文件、加密 UDP/MAC/PHY、真实 SDRAM 存储体和 HDMI 屏幕。本轮未做布局布线、时序闭合、正式播放器 bit 或网线实测，不能宣称已上板稳定。

## 大头仍需下一轮处理

现有 `udp_ip_protocol_stack_merge.enc.v` 是加密实现，公开参数只有设备、ARP 重试次数/延迟和本地地址等，没有关闭 ICMP、地址缓存或 ARP 模块的参数。本轮不解密、不修改加密块，也不以常量输入就已移除它们作承诺。

要明显缩减两套通用网络逻辑，需要另做可独立验证的固定双端 IPv4/UDP 端点，替换通用 UDP 栈，保留已测试的 MAC/RGMII/PLL 及应用包接口。必须核验固定 IP/MAC、网络字节序、IPv4 头校验、UDP 长度/校验策略、帧填充、MAC FIFO 背压、连续应用负载、错误包拒绝、复位和互通；不是本轮已完成的低风险删除。也不保证未经综合测量的资源收益。

当前正式 A/B 约束仍存在上一阶段记录的缺口。发布正式播放器 bit 前必须补齐正式引脚与时序约束并做布局布线，不能沿用早期 IMGF 测试 bit 当作正式播放器。

`backup_phase8_netopt/` 保存优化前双板 RTL、A/B 工程、资源报告及相关测试/脚本，是源码快照，不是独立可烧录工程。最终审计会检查只有上述三份生产 RTL 改变、工程清单及原单板顶层/bit 哈希保持不变。此前所有阶段固定记录不覆盖。
