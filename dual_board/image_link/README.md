## 固定分工

- A 板：主板，保留 HDMI、SDRAM、帧边界切换和本地危险预警；接收图像包后写入非显示缓冲区，完整校验并等待 SDRAM `write_finish` 后才允许提交。
- B 板：副板，持有唯一一张 TF 卡；BMP 解码/缩放为 640×480 RGB888，展开无损首页/音乐卡片图层索引，按 256 个 RGB+索引像素一包发送；PCM 按 128 个立体声样本一包发送。按 A 实际消费的样本数计算 VU、频谱、波形和歌词进度，通过 VIZ2 状态包供 A 渲染。电脑 UART 接 B，原文本命令通过 CTL2 发布目标参数；OK/STATUS 不是主板执行确认。
- 两板间传的是加载时的图像数据，不是逐帧 HDMI 视频。IMG4 中一张 640×480 RGB+索引图为 1228800 字节像素数据、1200 个包，原始宽高和缓存有效位同步提交。原图与图层仍可分开处理，不增加主板 SDRAM 帧数。保持现有单板 bit 作为回退。

## 资源可行性先决条件

当前最新主板 `logic_round3` 布局报告为 17393/19600 LUT、3/4 PLL；独立网口测试 A 板为 4292 LUT、2 PLL。两者**不能直接合并**。报告中的层级数不是可简单相加的最终预测，但指出必须把 TF/BMP、部分音频分析和副板生成的图文资源迁出。

时钟方案：A 板沿用现有 `sys_pll`（SDRAM 100 MHz）、`PLL_HDMI_AUDIO`（12.288 MHz），把 `video_pll` 替换为已测试的以太网 `pll_gen`，其 25/125 MHz 同时供视频/HDMI 与 UDP/RGMII TX；RGMII RX 保留 `rx_pll`。这样合计 4 个 PLL。该替换会影响 HDMI 时序，必须分别完成 A 板布局布线、仿真与上板验证，不能仅凭频率相同认定等价。

## 图像包 v1

本阶段选择较小的包和完整帧提交，避免在 FPGA 内堆积整张图：

| 字节偏移 | 内容 |
| --- | --- |
| 0–3 | ASCII `IMGF` |
| 4 | 图片缓冲区号 0–3 |
| 5–6 | 包号，小端，0–1199 |
| 7 | 位 0 = 图像源为 top-down BMP，其余位保留为 0 |
| 8–775 | 256 个 RGB888 像素，R、G、B 顺序 |
| 776–777 | 对字节 0–775 的 CRC-16/CCITT-FALSE，大端；初始 `FFFF`，多项式 `1021` |

每包 UDP 载荷 778 字节，低于普通以太网 MTU。接收侧先将一个包缓存到 256×24 位 BRAM，并在校验通过后按包序号输出像素；任何 CRC、长度、序号错误都会废弃当前整帧，不让部分图像上屏。首包号 0 可以重开一帧。后续要增加发送端重传/整帧重试、帧完成 ACK，以及 `frame_read_write` 的 `write_finish` 提交门控。

## 阶段边界

1. 先完成包格式、接收检查器与仿真，测正常包、损坏包、缺包和帧边界。独立合成量化接收端 LUT/BRAM。
2. 再做 B 板 TF 像素流跨时钟及发送端、A 板 SDRAM 写入和帧切换；分别做资源/时序验证。
3. 上板先传一张静态图，确认完整显示与故障时保持上一张图；然后再迁音频。

因此本目录新增的 RTL/仿真仅是链路组件，不表示完整媒体双板工程已完成。

## 2026-10-04 可上板的大数据链路测试

独立 A/B 测试工程已生成 bit。B 生成一幅确定的 640×480 测试图，经真实 UDP/RGMII 发往 A；A 逐像素核对收到的 RGB，并检查包 CRC、顺序和完整帧。该测试不需要 TF 卡，HDMI 尚未接入。

| 布局布线后的指标 | A：接收检查 | B：生成并发送 |
| --- | --- | --- |
| LUT | 4103 / 19600 | 4223 / 19600 |
| 寄存器 | 3341 | 3477 |
| BRAM9K | 12 | 12 |
| PLL | 2 | 2 |
| 最差建立裕量 | +0.028 ns | +0.038 ns |
| 最差保持裕量 | +0.003 ns | +0.011 ns |

B 使用布局种子 29；以上为当前报告和约束下的结果，尚待板上验证。现有约束仅包括系统、RGMII 接收时钟及 IP 约束，STA 覆盖约 99.6%；不能把这个结果当作最终 HDMI/SDRAM 工程的时序结果。

烧录文件：`prj/board_a/IMAGE_LINK_A.bit` 给 A；`prj/board_b/IMAGE_LINK_B.bit` 给 B。先用 PROGRAM_SRAM 分别下载，网线接此前已通过测试的网口，两板供电。K1 是复位；**发送按键是 B 板 K2**。

1. 两板复位，等待约 2 秒。
2. 按住 B 的 K2 约 3 秒，让它连续发送若干完整帧，然后松开。
3. A 第一盏 LED 是心跳；第二盏表示收到有效图像包；第三盏表示至少一张完整图片的所有像素核对通过；第四盏表示包错误或当前帧像素错误。以状态变化判断，不依赖灯的有效电平。
4. B 第二盏表示已经发包，第三盏表示已经发完一整帧。K2 松开后已经开始的帧会继续发完。
5. 重复复位、发送数次。A 第三盏出现完成状态且第四盏保持复位状态，才说明大数据链路上板检查通过。单纯第二盏变化只证明收到了包。

本阶段使用固定包间隔和单包缓冲。接入 SDRAM 前必须增加接收反馈、流控及超时重试；SDRAM 完整写入后再提交显示缓冲区，不能直接沿用固定间隔假设。
