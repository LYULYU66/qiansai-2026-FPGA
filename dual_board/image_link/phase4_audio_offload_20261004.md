# 第四阶段：副板音频分析与歌词计算

## 本轮结果与边界

B 已承担左右声道 VU、16 段频谱、时域波形、歌词时间轴及逐像素唱红进度计算；A 保留现有显示布局、字库、音量输出、危险开关、报警混音和最终 HDMI。不是迁移整个歌词绘图模块，也不是副板发送逐帧 HDMI 视频。

改动仅在 `dual_board/image_link/`。原单板 HDL 与已验证 bit 没有更改。本轮尚未布局布线、闭合时序或生成正式双板播放器 bit；无网线，因此没有本轮上板验证。先前 IMGF 图案测试 bit 不能与当前工程混配。

## 同步与低资源实现

1. A 的音频 FIFO 实际读出一个立体声样本时累计播放计数，以 Gray 码同步到 UDP 域。它是实际消费进度，不是按网络包到达时间或 TF 读取速度推算。
2. A 通过 AAK3 确认包反馈会话、块号、消费计数、音量 0–8 和分析开关。首个有效音频块确认后，每约 1 ms 补发状态；断流期间计数不变，控制仍可更新。
3. B 保存已经交给音频发送器的原始 PCM 到 1024×32 位短历史 RAM，只有收到同会话、非倒退且不超出已写样本数的反馈后才分析对应样本。896 字背压阈值防止覆盖尚未分析的数据，不缓存整首歌。
4. B 分析时钟复用以太网 PLL 已有 25 MHz 输出，无新增 PLL。两个 Gray 指针跨 25/125 MHz；控制和视觉状态通过保持数据直到确认的 mailbox 跨时钟，复位异步置位、分域同步释放。
5. PCM 增益与现有 I2S 播放器同为移位加法 0/8–8/8，无新增增益乘法器。样本间至少留 256 个分析时钟，超过现有 Goertzel 最坏 192 拍运算时间；待计算收敛后才发布状态。
6. B 默认约 60 次/秒发送可替换的 VIZ2 状态；不重传旧可视化帧。A 校验 CRC、长度、会话及进度，拒绝超前/倒序状态，只有在 VS 才整体更新，不在画面中途撕裂。
7. 一个完整 UDP 核复用两级小仲裁器，优先级为 PCM、可视化状态、图片。包内不抢占；发送器中途复位时沿用填充错误 CRC 的退出保护。

正常网络下可视化存在反馈、分析和显示刷新延迟，并非零延迟；音量改变也通过反馈传播，并不是逐样本发送主板增益历史。若网络阻塞，显示保持最近的有效状态，歌曲进度不会按墙钟自行向前。

歌词仍只适用于现有 40174240 字节、48 kHz、16-bit 立体声 `MUSIC.PCM` 及其已配套的时间轴。多首歌曲管理、LRC 在线装载不在本轮范围内。

## 包格式

### AAK3：18 字节，A → B

| 字节 | 内容 |
| --- | --- |
| 0–3 | ASCII `AAK3` |
| 4–7 | 音频会话 u32，小端 |
| 8–9 | 已接收块号 u16，小端 |
| 10–13 | 累计实际消费样本数 u32，小端，歌曲循环不清零 |
| 14 | 位 3:0 = 音量 0–8，位 4 = 分析开关，位 7:5 = 0 |
| 15 | 保留，必须为 0 |
| 16–17 | 字节 0–15 的 CRC16/CCITT-FALSE，大端 |

旧 AAK2 仍由默认参数支持，用于原组件回归；新 A/B 播放器均启用 AAK3。

### VIZ2：47 字节，B → A

| 字节 | 内容 |
| --- | --- |
| 0–3 | ASCII `VIZ2` |
| 4–7 | 音频会话 u32，小端 |
| 8–11 | 本状态对应的已分析样本数 u32，小端 |
| 12–44 | 264 位紧凑状态，最低字节先传 |
| 45–46 | 字节 0–44 的 CRC16/CCITT-FALSE，大端 |

264 位映射：`[6:0]` 左 VU，`[13:7]` 右 VU，`[125:14]` 16×7-bit 频谱，`[237:126]` 16×7-bit 有符号波形，`[245:238]` 当前歌词行，`[253:246]` 下一行，`[263:254]` 唱红像素数。谱/波的含义、原有平滑算法和现有绘图布局不变。

47×60 ≈ 2820 字节/秒可视化载荷；AAK3 周期反馈约 18000 字节/秒载荷，不含 UDP/以太网开销。没有额外整帧网络视频流。

## ModelSim 验证

最终 13 项整轮回归全部通过，2026-10-04 11:29:05 开始、11:34:00 完成，ModelSim Starter 10.5b。编译与仿真没有错误或 Fatal；两项使用原双 FIFO 的测试各保留 6 条未使用端口警告，共 12 条，不是零警告。

沿用前 9 项：图片 CRC/丢包检查、1200 包整帧、像素跨时钟、可靠图片重传/提交、SDRAM 写保护接口、缓存切图、PCM 接收防护、发送中止保护，以及真实 FIFO + 48 kHz 播放与断流恢复。

新增 4 项：

- `tb_audio_status_guard`：AAK3 编解码、首次确认前不发送状态、冻结计数时仍更新音量、CRC/长度/截断/保留位/非法档位/协议版本拒收。
- `tb_audio_visual_guard`：264-bit 负载完整性，CRC/长度/截断/会话/倒序/超前拒收、丢包后的新状态替换、同进度刷新、VS 原子更新。
- `tb_remote_compute`：25/125 MHz 双时钟历史 RAM、896 字背压、0–8 增益、环形 RAM 与 32-bit 计数回绕、错误/旧反馈拒收、歌词消费计数及精确 EOF。EOF 和 32-bit 回绕采用一致状态的仿真注入，不代表已做 24 小时实机测试。
- `tb_audio_offload`：真实原 100/125 MHz TF 侧 FIFO、A 的 PCM FIFO及 12.288 MHz/48 kHz 播放器；图片/PCM/视觉三流复用；CRC 破坏、ACK 丢失、14.4 ms 断流、恢复及新会话；分析输出逐拍对照原分析器，且逐样本验证原始 PCM 顺序/增益，检查没有在 Goertzel 忙时丢输入。

首次两个元数据测试曾因测试端未等计数更新/CDC 同步而失败；只修正测试采样/等待时刻后通过，未屏蔽失败检查。前次失败日志保留，可追溯。

日志：`sim/modelsim_regression.log`。新增波形：`audio_status_guard.wlf`、`audio_visual_guard.wlf`、`remote_compute.wlf`、`audio_offload.wlf`。原 FIFO 未使用端口 `doa/dib` 的模型警告保留，不改动原 IP。

重跑：工程根目录执行 `& ./dual_board/image_link/sim/run_modelsim.ps1`；快速元数据检查可加 `-Suite Guard`。两板资源构建：分别进入 `prj/media_a`、`prj/media_b`，用 TD CLI 执行 `build_gate.tcl`。

这些是行为/接口仿真，没有模拟加密 UDP/MAC 和真实 PHY、完整 TF 文件系统、SDRAM 存储体或 HDMI 屏幕。已有独立 TF 包装模块仅编译并零时刻展开，不代表真实卡读验证。
