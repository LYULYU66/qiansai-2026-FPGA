# 第七阶段：断链、独立复位的会话保护基础

本阶段只改双板 `image_link` 隔离工程，单板源码/bit 不改。两板固定分工不变：B 读取 TF 并计算媒体状态，A 缓存图像、实际播放、最终渲染并处理本地危险预警。

## 本轮完成范围

- `LNK1` 应用层握手与心跳：A 分配 16-bit generation；B 先申请、收到 OFFER 后保持媒体复位 64 个 UDP 时钟，再发 ALIVE；A 收到匹配 ALIVE 才接受媒体。正常心跳间隔 100 ms，500 ms 无有效回应则停止该会话。单向断路也能触发超时，可能需两个超时窗口才能两侧均失效。
- IMG4 token/AUD2 session 的高 16 位使用 generation，低 16 位保留图像加载/音频流编号。包大小不变；旧 generation 的首包、连续包、重复包均不能写图像或输出新 PCM。低 16 位将耗尽时 B 请求换 generation，而不是静默重复会话号。
- A 会话失效只中止未完成的图像写入，不清掉已提交的四帧有效位和原始分辨率；仍禁止写当前显示/转场中的受保护缓冲区。图片缓存的跨域快照不再受网口局部复位清零。
- A 音频失效清接收/FIFO、实际播放头和可视化会话。音频使能跨域同步器增加 FIFO 异步清零，确保 128 ns 的短复位也能让 12.288 MHz 串行器清掉旧播放状态，重新等待 256-word 预缓冲。I2S 时钟不随会话重启而重置；旧立体声帧允许在正常边界结束，之后无数据则静音。
- B UART 与目标参数只随本板基础复位清零，不受媒体租约重建影响。所有包边界仲裁器也独立于媒体局部复位，仍用坏 CRC 补齐已请求 UDP 包，避免半包使 MAC 等待缺失尾部。

短时丢包且没有达到心跳超时，继续沿用原 stop-and-wait、CRC 重传与真实消费计数冻结/恢复。长时断链重新协商，会触发 B 的 TF 媒体读取重新开始，**不是断点续播**。

## 仍未完成的边界：不要把握手恢复当成播放器完全恢复

B 单独重启或长时间断链后会重载第一张图片；如果 A 手动停在这一页，它的缓冲区受到保护，仍会拒绝重写。B 的四图预载不能完成，PCM 可能因此不能重新开始。本轮没有绕开保护、没有添加第五帧，也没有假 ACK。下一轮应增加相同图像的内容校验/安全缓存复用；换了 TF 图片时还要另行处理不同内容，不能只凭图片编号认定相同。

A 单独复位会清自身缓存，握手让 B 更换会话并重新加载，但本阶段只仿真了握手、媒体包接收、缓存保护等组件；未完成真实 TF → MAC/PHY → SDRAM → HDMI 的端到端上板复位测试。

generation 是易失的可靠性编号，不是认证。两板同时冷复位都失去历史、16-bit 世代长时间回绕、任意旧握手包恶意重放不在本轮安全保证内。CTL2 参数包沿用上一阶段格式，未新增跨世代认证，周期目标参数会重新发布。MAC/PHY、PLL 和引脚约束没有为本轮做修改。

## LNK1 包（10 字节，同 UDP 端口 0x5002）

| 偏移 | 内容 |
| --- | --- |
| 0–3 | ASCII `LNK1` |
| 4 | 0 REQUEST、1 OFFER、2 ALIVE、3 ACK |
| 5 | 保留，必须为 0 |
| 6–7 | generation / 请求时的上次 generation 提示，小端 |
| 8–9 | CRC16/CCITT-FALSE，大端，覆盖字节 0–7 |

A 健康会话期间忽略 REQUEST，避免延迟旧请求打断播放；重启的 B 要重试至旧租约超时。B 等待协商时不接受 ACK 作为新会话，只接受发出 REQUEST 后的 OFFER；带历史编号时须更新 generation。
