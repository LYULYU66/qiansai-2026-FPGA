# 正式双板播放器：副板跨域复位与音频元数据

本轮完成独立的 B 第四轮硬件候选：原单板、固定 UDP 诊断 bit、第十阶段正式源码与第十一阶段候选均未改动。A 仍用上一轮 R3 候选；**没有发布或烧录新的正式播放器 bit**。此前用户报告 LED 正常仅代表独立网口诊断通过，不是媒体播放器实板通过。

## 本轮修改

修改仅存在于 `rtl/hw_round4_20261005/`，未删除功能、改变协议或增大缓存：

1. B 的 UDP、SD、电脑串口及音频计算状态分别在所属时钟下同步释放复位；异步请求仍能在时钟停止时立即置位。图片装载中止只清理桥接数据，装载编号保持递增，不复用失败帧的 token。
2. PCM 文件长度不再直接供多个跨域消费者使用。在原有 stream 三拍同步握手上升时，统一锁存 UDP 域的样本数与 session；播放过程中保持不变。新一轮音频和新链路生成号仍分别更新。
3. 歌曲匹配判断先在 UDP 域比较已锁存的长度，再把单比特结果同步到 25 MHz 计算域。频谱、波形、歌词时间轴和主板实际播放头的同步规则不变。
4. 状态邮箱和计算模块的局部复位输出使用本地释放寄存器，不再把原始复位请求 OR 回释放后的输出。

沿用上一轮音频积压量流水化、1024 样本历史 RAM/最大 896 样本占用、首页 ROM 流水。PLL、引脚、HDMI/SDRAM/MAC 核、FIFO 深度、时钟频率和 SDC 均未改变，也没有新增整时钟域 false-path。

## 剩余时序与下一步

时序没有闭合。当前 B UDP 同域最差 setup 为 −1.721 ns，涉及图片发送 RAM 输出、字节选择和 CRC；SD 同域约 −0.504 ns，涉及 BMP 地址/缩放；跨 SD→UDP 的元数据与 Gray 路径仍有约 −1.540 ns 保持违例。最差 recovery 为 −3.374 ns，物理报告还存在复位请求到映射后的 SD 域 SR 端点。

本轮证明的是 RTL 同步释放与握手稳定性；**不能把该结果当成物理网表已消除所有异步复位扇出或 CDC 时序违例**。下一步先审计映射后的同步寄存器/复位端点和稳定元数据窗口，再对具体端点设置有证明的约束；同时局部流水化 RAM→字节选择→CRC，保持连续包长、尾 CRC 和残包排空。不放宽整个 25/100/125 MHz 关系、不堆 FIFO 深度。A 的进度判断和原有 SDRAM IO 负路径仍需单独处理。

## 复现

从工作区根目录运行 `dual_board/image_link/sim/run_player_round4.ps1 -Suite All`、`-Suite Guard`、`-Suite Boundary`。ModelSim 串行运行，不同时启动多份仿真。DO 和 WLF 均保存在本轮独立目录。

TD 在 `prj/media_b/` 下执行 `build_round4_b.tcl`；脚本无自动 bitgen。所有日志完整后，从工作区根目录运行 `node dual_board/image_link/sim/snapshot_player_round4.js <本次TD日志文件名>` 重新校验基线并生成本轮清单。`prepare_player_round4.js` 是首次创建候选的机械生成器，重新执行会重建本轮项目/DO，复核既有清单时无需运行它。
