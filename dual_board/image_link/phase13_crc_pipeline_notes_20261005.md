# 副板图片发送：RAM 到 CRC 的低成本流水化

本轮完成 R5 图片发送候选的代码、ModelSim 和完整布局布线。它是**时序优化实验候选，不是新发布的正式播放器 bit**；原单板、固定 UDP 诊断、正式第十阶段和 R4 候选均保持不变，A 沿用 R3。

## 改了什么

唯一新增的硬件替换文件为 `rtl/hw_round5_20261005/image_packet_tx_hw.v`。在包缓存 RAM 与字节选择/CRC 之间增加 24/32 位像素保持寄存器：

- 下一像素在当前像素倒数第二字节时预读；最后一个字节仍使用当前保持值，随后锁存新像素。
- 第一像素在包头结束前装入；每个重传包重新预读，复位后新包也一定先装入有效数据。
- 这个临时寄存器无需复位清零，不增加 BRAM、第二包缓存或 FIFO 深度。
- 有效发送字节、valid、request、source_ready、包长、帧提交、CRC、序号和重传节拍保持逐拍一致。无效周期的 udp_data 不作协议承诺。

项目 `prj/media_b/MEDIA_SOURCE_B_R5_HW_20261005.al`，脚本 `build_round5_b.tcl`。其余 RTL、ADC、SDC、PLL、IP、缓存和协议与 R4 相同。没有为获得正裕量而新增时钟组切断或 false-path。

TD 日志 `prj/media_b/td_20261005_144410.log` 完成 route，无 ERROR；最终报告 Confidence=Routed，种子 1。

UDP 同域改善 0.937 ns，原图片 RAM→CRC 路径不再位于本次最差 setup 列表；不能据此宣称所有图片路径或整个 UDP 域已闭合。代价为布局后 +45 LUT、+30 寄存器；综合为 +57 LUT、+32 寄存器（11227/7668 → 11284/7700）。这是小幅资源换时序，不是进一步减少 LUT 的版本。没有功耗实测，不声称流水化已经降低功耗。

全局 recovery 和 SD 同域布局结果反而略差，故 R5 只作为局部优化候选，R4 保留作独立对照。当前仍不能生成已通过时序的正式播放器 bit。A 本轮未重新构建，沿用 14280 LUT（72.86%）、BRAM9K/32K=50/7、DSP/PLL=3/4；原全局负裕量仍在。

## 本轮 ModelSim 证据

1. 新增逐拍对照：冻结原始图片发送模块只改模块名作为 golden，与候选并行接受相同输入。6 组参数覆盖 IMGF/IMG2/IMG3/IMG4、RGB 与 RGB+索引、内外部 token、尺寸元数据；核对 196920 个时钟、154 个完整包和 36 次完整帧发送。另用独立 CRC 算法检查每包，测试错误/丢失 ACK 重传、连续帧，以及包头末尾、像素预读/捕获交界和 CRC 尾部的窄脉冲复位。0 错误、0 警告，日志 `sim/hw_round5_20261005/modelsim_guard.log`；波形 `image_tx_pipeline_equiv.wlf` 记录 RAM/保持寄存器/字节相位/CRC 与 golden 字节。
2. 按 R5 替换源重新运行全部原有 40 项回归：全部通过，0 错误、106 条原有可选端口/原生 FIFO 警告消息。图像 CRC/重传、缓存保护和复用、控制/尺寸、音频实际播放头同步、固定 UDP 原生 FIFO及多次重启覆盖均保留。日志 `sim/hw_round5_20261005/modelsim_all.log`。
3. 重跑实际 B 应用顶层边界测试：640 个 PCM 样本逐字核对、长度冻结、串口控制、残包排空/错误 CRC、重连后会话、三次图片中止恢复均通过。该测试替换 PLL/网络引脚传输和已解码 SD 输出，不是实卡或 PHY 验证。
4. 在独立仿真实例中再次跑全帧源核对：614400 个 RGB+索引字、两种存储方向、尺寸元数据和回压全部通过。后两项日志 `sim/hw_round5_20261005/modelsim_boundary.log`，0 错误、11 条既有端口警告消息。

统计为 43 次测试执行：原有 40 项、一个新的逐拍测试（内部 6 组参数）、一个沿用的顶层边界测试，以及一次重复全帧源测试。原始测试与断言没有修改；完整文件哈希和物理负路径见 `phase13_crc_pipeline_validation_20261005.json`。这些不是完整 TF/FAT、物理 MAC/PHY、HDMI/SDRAM 或正式播放器实板验证；此前用户确认的灯光正常属于独立网口诊断。

## 接下来优先处理

1. 当前 UDP 同域最差端点已转到音频确认解析与状态控制，另有可视化短包选择到调度器 CRC 的约 −0.523 ns 路径。先考虑把确认包末字节的 CRC/包资格判断寄存，保持现有有效脉冲、完整包检查和迟到确认过滤；继续逐拍对照，不直接删判断。
2. 当前全局 recovery 主要落在原生 FIFO `asy_w_rst1`、图片复位释放链等异步请求端点。先区分同步释放链自身的 SR 检查与真正的下游逻辑复位，再审计 Gray 第一拍与握手保持的元数据；约束只能作用于已证明的具体端点，不能整域 false-path。
3. 流水级使字节相位具有“只在有效像素内非零”的不变量，可另做重复范围解码简化实验以降低新增 LUT，但需要独立仿真和物理报告。本轮尚未采用该简化。
4. A 的进度判断、原有 SDRAM IO 负路径和外部 IO 延迟仍需分别检查；不改加密核、PLL 相位或 SDRAM 仲裁。

## 复现
