# 第六阶段：副板串口控制与图片原始尺寸

2026-10-04。仅修改隔离的 `dual_board/image_link/` 分支，单板源码和可回退 bit 保留。本阶段仍为行为/接口仿真和 gate 综合，**不是布局布线通过，不是可烧录的双板媒体播放器发布**。

## 两板协作原则：并行，而非简单相加

- B 是媒体源与计算/交互板：唯一 TF 卡、BMP/FAT/缩放、静态 UI 索引展开、PCM 读取、频谱/波形/歌词进度计算、电脑 UART。
- A 是确定时序的输出与安全板：SDRAM 缓存/转场、HDMI 音视频、图层最终绘制、统一时钟、拨码危险和本地报警。
- A 在显示/播放当前内容时，B 可以读取、发送下一张图和准备 PCM；图片只在加载时传输，不逐帧占用网口。
- B 按 A **实际消费**的音频样本进度和实际应用的音量计算，而不是按网络发送进度计算，避免网络抖动拖走歌词/可视化时间轴。
- 非可视化页面沿用分析器的低功耗使能；跨时钟邮箱仅在状态变化时更新。网络控制有周期重发以容忍丢包，不追求无条件关闭必要时钟。
- 资源必须分别查看 LUT、BRAM9K/32K、DSP、PLL 和最终时序；两块板的空闲资源不是一块共享芯片。A 已用 4/4 PLL，新增功能不能默认再加 PLL。

后续先完善独立复位/断链恢复及正式约束/布局布线；之后再量化优化多路发送仲裁、共享 CRC 等热点。若增加副屏仪表，属于新增显示链路，须单独验证，不把当前“副板计算、主板显示”宣称为两屏均已输出。

## UART 迁移及回复含义

B 复用未修改的 `uart_audio_control`、`uart_baud_tick`、`uart_rx`、`uart_tx`。115200 baud、8-N-1，大小写不敏感，以 CR、LF 或 CRLF 结束：

| 文本命令 | 含义 |
| --- | --- |
| `VOL 0` … `VOL 8`、`VOL+`、`VOL-` | 音量 0–8，增减有边界钳位 |
| `MUTE`、`FULL` | 静音、音量 8 |
| `BRI 25/50/75/100` | 图片亮度四档 |
| `CON 25/50/75/100` | 图片对比度四档 |
| `STATUS` | B 已接受的目标参数 |
| `PING` | B UART 返回 `PONG` |

上电目标值仍是 VOL=8、BRI=100、CON=25。回复字符串保留，**OK 和 STATUS 只表示副板接受/报告目标参数，不表示主板已确认执行**。断网时 B 能正常回复 UART，但 A 保持最后有效参数；恢复通信后周期重发最新参数。正常链路延迟包括最长约 10 ms 的发送周期、包边界仲裁、跨时钟握手和等待视频帧边界，未做真实网线延迟测量。

A 删除电脑 UART 端口和解析器。B 增加 UART 引脚约束 RX=F12、TX=D12，来自未修改单板 `pin.adc`；电脑应接 B 的板载串口通路，JTAG 烧录连接不等于串口连接。正式媒体工程其余引脚/时钟约束仍需后续完成，不能用目前 gate 报告判断板上引脚已全部正确。

50 MHz 解析后的 `{CON[1:0],BRI[1:0],VOL[3:0]}` 用 8-bit 握手邮箱跨到 125 MHz，避免三项不同步；A CRC 校验后再跨到 25 MHz，并在 VS 一起更新。没有增加命令大 FIFO、整首音乐存储或额外 PLL。

## CTL2 控制包

| 字节 | 内容 |
| --- | --- |
| 0–3 | `CTL2` |
| 4–7 | 每次发包递增的 u32 序号，小端 |
| 8 | CON 两位、BRI 两位、VOL 四位 |
| 9 | 保留，必须为 0 |
| 10–11 | CRC16/CCITT-FALSE，大端，覆盖 0–9 |

同一 UDP 端口 0x5002，B 默认每 10 ms 重发最新状态。A 拒绝 CRC/魔数/长度/保留位/音量范围错误和过期序号；丢包不需要堆积或重放全部历史命令。没有 1 秒内被接受的控制包时允许序号重新基准化，以接受 B 重启后的序号 0，但保持原参数直到新有效包到达。此策略只恢复控制通道，**不代表独立板复位后的媒体会话已完整恢复**。

B 在包边界按 PCM > 控制 > 可视化 > 图片仲裁，已开始的图像包不被抢断。没有提高音频缓存深度。

## IMG4 原始图片尺寸

IMG3 增加四个头字节升级为 IMG4，A/B 正式媒体分支必须成对更新。历史 IMGF/IMG2/IMG3 默认组件模式保留；老测试 bit 不改动。

| 字节 | 内容 |
| --- | --- |
| 0–3 | `IMG4` |
| 4 | 缓存号 0–3 |
| 5–6 | 包序号 u16 LE |
| 7 | BMP top-down 标志 |
| 8–11 | 加载会话 token u32 LE |
| 12–13 | BMP 原始宽度 u16 LE |
| 14–15 | BMP 原始高度 u16 LE |
| 16–1039 | 256 个 R/G/B/图层索引像素 |
| 1040–1041 | CRC16 大端，覆盖 0–1039 |

每包 1042 字节；相比 IMG3 每帧仅多 4800 字节头部，像素格式和四帧缓存不变。缩放仍在 B，HDMI 固定输出 640×480；左上角显示的是对应 BMP 的**原始**分辨率。低于 640×480 的源不新增放大通路。

单板 SD 包装模块的原 `source_resolutions` 直到加载完成后才更新，不能用于正在发送的首包头。本轮复制为隔离的 `sd_card_bmp_remote`，仅改模块名并暴露现有 `source_width/source_height`；没有改 SD/FAT、双线性算法或 PCM 读取实现。B 在接受 BMP 写请求时锁定尺寸，在首像素发送时再锁定到传输会话。

A 校验尺寸下限，并检查同会话后续包/重复包的尺寸一致性。尺寸只在收到整帧且 SDRAM `write_finish` 完成后提交；缓存有效位与四幅尺寸经同一 132-bit 握手邮箱跨至视频域，防止新缓存比尺寸先可见。有效性撤销保留原两拍快速同步路径，不等待下一次 VS；恢复有效则等待尺寸快照。左上角沿用原清晰字模和无框参数行；没有新增字体库。

还修复同 token 首包尺寸不一致时可能被误当成新帧的边界：合法重复包只重 ACK，不重复写；新帧须有新 token。

## 资源：gate 综合

| 指标 | A 第五阶段 | A 本轮 | B 第五阶段 | B 本轮 |
| --- | ---: | ---: | ---: | ---: |
| LUT / 19600 | 14919 / 76.12% | 15083 / 76.95% | 12227 / 62.38% | 13211 / 67.40% |
| 寄存器 | 10442 | 11088 | 9347 | 9786 |
| BRAM9K / 64 | 49 | 49 | 27 | 27 |
| BRAM32K / 16 | 7 | 7 | 9 | 9 |
| DSP / 29 | 3 | 3 | 3 | 3 |
| PLL / 4 | 4 | 4 | 3 | 3 |

本轮 A 净增 164 LUT，B 净增 984 LUT；**不把“UART 移走”误说成本轮总 LUT 必然下降**。A 移出的原 UART 层级约 430 LUT，但控制接收/尺寸存储与跨域、恢复动态尺寸十进制格式化也要逻辑。相对第五阶段 BRAM、DSP、PLL 均不增加，A 相比第四阶段仍少 1617 LUT。资源没有按 50:50 强行平分，A 保留固定时序/安全链路，B 承担可迁移任务。

两板仍启用 `gate eram_init on`。报告只能说明当前门级映射容量可放下，不能据此证明布局、布线、时序或板上稳定性。原加密 IP 的既有综合警告也未屏蔽。
