# 双板图像链路第二阶段：IMG2 可靠传输与顶层资源验证

这是图像阶段的历史记录。后续 PCM 接入和当前资源见 `phase3_pcm_20261004.md`；图像阶段完整 A/B 综合报告已另存为各项目中的 `*_image_only_gate.area`，`*_gate.area` 现在对应后续阶段。

本阶段源码和报告位于 `dual_board/image_link/`。既有单板源码、单板 bit 和 IMGF 测试 bit 保留。新增主、副板顶层分别为 `rtl/top_dual_image.v`、`rtl/image_media_board_b.v`。

## 已连接的实际模块

B 板复用当前 `sd_card_bmp`、`bmp_read`、双线性缩放及 SD SPI 控制器。TF 卡读侧仍为 100 MHz，通过 1024×24 位异步像素 FIFO 接到 125 MHz 网口发送侧。FIFO 使用 Gray 指针、双级同步、每个时钟域同步释放复位，并预留 32 字余量。只缓存少量像素，不保存整张图片。

A 板 `image_main_ingress` 接收包、检查 CRC、顺序和传输编号，通过 `image_sdram_sink` 对接原 `frame_read_write`。写入侧时钟改为 UDP 125 MHz，SDRAM 存储接口仍使用原 100 MHz 时钟。首次写入前等待写请求确认，最后一个包等待 SDRAM 的 `write_finish` 跨时钟 toggle，然后才设置缓存有效标志、发送最后确认。四个 SDRAM 图片区、转场、HDMI 显示路径继续复用。

主板新顶层共享以太网时钟生成器的 25/125 MHz 输出给视频和 HDMI，省去独立 video_pll；加上 SDRAM 系统 PLL、HDMI 音频 PLL 和 RGMII RX PLL，合计 4 个 PLL。最终相位关系和路径裕量还须布局布线验证。

主板新切图控制只选择已经完整提交的图片。手动切换、1 秒自动切换、预警时暂停自动轮换均已加入。原预警模块仍负责直接进入第四页和本地报警。可见图片及转场涉及的缓冲区会被保护，接收器不能向这些区域启动新写入。

## IMG2 协议

| 字节 | 内容 |
| --- | --- |
| 0–3 | ASCII `IMG2` |
| 4 | 图片区号 0–3 |
| 5–6 | 包序号，小端，0–1199 |
| 7 | bit0=top-down；其余为零 |
| 8–11 | 32 位传输编号，小端 |
| 12–779 | 256 个 RGB888 像素 |
| 780–781 | 字节 0–779 的 CRC16/CCITT-FALSE，大端 |

ACK 为 12 字节：`IAK2`、32 位传输编号小端、16 位包序号小端、CRC16 大端。UDP 端口为 `0x5002`，IP/MAC 沿用此前 A/B 网口测试的配置。

发送器同一时间只保留一个未确认包；确认后才接收下一包的像素。100 ms 没有收到对应确认便重发原包，编号和数据不变。接收器对已消耗包的重发只重复确认，不重复写像素；错误包不推进序号，等待发送器重试。最后一包的确认丢失后也可以安全重发。B 的传输编号在普通装载中止时不回退。

如果 A 长时间收不到数据或 SDRAM 长时间停顿，2 秒超时中止写入，清空接收状态，保持其它有效缓冲区。B 仍沿用原 TF 装载看门狗处理重试。当前首次启动和独立板卡复位后的恢复仍建议两板一起复位；自动协商新会话、重新发送已缓存图片尚未加入。

旧 IMGF 固定间隔测试通过参数 `RELIABLE=0` 保留。IMG2 顶层不能和此前 IMGF 测试 bit 混配。

## 实际验证

ModelSim Starter 10.5b，2026-10-04 最终回归成功，编译、仿真零错误、零警告：

- 原 IMGF 接收检查与 1200 包整帧回归仍通过。
- IMG2 1200 包、307200 像素，注入一次数据损坏、首包和尾包确认丢失、长时间写侧暂停、延迟 SDRAM 完成，最终通过，像素无重复或丢失。
- 100/125 MHz FIFO 4096 像素跨时钟比对、指针多次回绕和接收暂停通过。
- 保护可见缓冲区、停顿超时中止、禁止提交部分帧通过。
- 缓存有效标志同步、手动/自动切图、预警暂停通过。
- 实际 TF 顶层与原生 BRAM32K 模型已完成 ModelSim 编译和连接展开；这一项不是完整 SD 卡文件读取行为仿真。

## 交付边界与下一步

本阶段新增顶层完成源码连接、可靠传输行为仿真和综合资源检查，尚未生成新的正式播放器 bit，也没有进行网线或 HDMI 板上验证。

A 图片顶层保留本地串口、画面叠加及报警。正常 PCM 暂时静音，尚未迁移网络音频、歌词、分析结果和首页绘制。状态栏暂显示 640×480 输出分辨率，B 已解析的原图分辨率还需后续控制包传递。音乐相关显示在此图像验证版本中不代表音乐已完成迁移。

后续先增加网络 PCM 缓冲和播放样本序号同步，再迁移音频分析/歌词与电脑控制，继续释放 A 的 LUT/BRAM。随后为两板分别补齐约束、布局布线和新 bit，最后有网线时验证 TF→UDP→SDRAM→HDMI 的真实链路。
