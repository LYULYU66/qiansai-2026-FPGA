# 双曲 KEY3 上板测试版（2026-10-06）

已完成两首完整 PCM 的共用读取、KEY3 手动切换、封面和歌名联动、两行歌词及已唱红色进度。上电默认告白气球，按一次 A 板实体 KEY3（B1）切至一路向北，再按一次切回；新歌从头播放，当前歌播完循环，不自动换歌。KEY1 复位，KEY2/KEY4 原图片功能保持。

## 下载与 TF 文件

1. A 板：MEDIA_A_DUALSONG_KEY3_20261006.bit。
2. B 板：MEDIA_B_DUALSONG_KEY3_20261006.bit。两板都必须更新，不混用旧协议版本。
3. 先用 TD 的 PROGRAM_SRAM 下载，暂不固化 FLASH。
4. TF 卡仍插 B 板。将本文件夹 TF_CARD 内 MUSIC.PCM 和 MUSIC2.PCM 复制至原卡根目录；四张 BMP 保持原样。原告白气球若已是本工程完整长度 40174240 字节，可只补 MUSIC2.PCM。不要把 MP3 或带 WAV 头的文件直接改名。
5. 音频均为无文件头、48kHz、16-bit 小端、有符号双声道交错 PCM。两首共约 97.35 MB，不占用整首片上 RAM。

## 实现与资源

两首共用 TF/FAT 读取、音频 FIFO、UDP 发送、频谱/波形分析。AAK3 的保留字节新增一位切歌请求并受 CRC 保护，包仍为 18 字节，不另建控制通道。B 先停旧音频扇区，等待读取结束，再切元数据并留 16 个 SD 时钟的复位间隔；图片缓存不重置。丢包通过周期重发最终请求，旧会话命令被拒绝，缺少第二文件时维持当前歌曲。

歌词共用一套 24px 抗锯齿字库和同一个显示读口；一路向北新字模增加 3 个 BRAM32K，B 歌词事件多 1 个 BRAM9K。封面为 40x40 圆形、15 色加白底，共 1 个 BRAM9K，音乐页扩至 64x64；首页标题复用歌词字库，无新字体 ROM。其余卡片、图片、预警、串口、字幕、音量及亮度/对比度沿用基线。

完整布局布线后的资源，不是综合估算：

| 资源 | A 主板 | B 媒体板 |
|---|---:|---:|
| LUT | 14763（75.32%） | 11699（59.69%） |
| 寄存器 | 9270 | 7922 |
| BRAM9K / BRAM32K | 51 / 10 | 29 / 9 |
| DSP / PLL | 3 / 4 | 3 / 3 |

相对 R10 候选，LUT 合计增加 605；相对已验收 R7A/R8B 合计增加 132。布局变化也会影响 LUT 数字，不能将差值全归到切歌逻辑。

## 验证与限制

5 组 ModelSim 日志中共 11 个 PASS：双目录顺序/碎片簇/背压/中途切歌/循环，缺失文件与 KEY3 去抖/CRC 错包，731 个歌词事件/停读冻结/EOF，4 个完整显示帧及 64372 个旧字模像素，实际 B 顶层双曲会话/旧命令过滤/串口/重连和 614400 图片字，真实 48k 播放反馈、频谱波形参考等价、音量、丢包重试及四通道仲裁。日志位于 evidence。较旧测试台的未用端口连接产生警告，已核对与这次启用的双曲接口无关；行为仿真不证明物理时序可靠。

时序仍未闭合：A 建立 -5.699ns、保持 0.004ns、UDP 同域 -2.33ns、视频同域 0.173ns；B 建立 -3.566ns、保持 -1.54ns、UDP 同域 -0.896ns、SD 同域 -0.603ns。A UDP 负裕量比 R10 更差，不能保证长期板上稳定。另一 A 种子路由失败没有 bit；另一 B 种子虽改善 UDP，但 SD 变差，未选。没有改 PLL、引脚（新增空闲 KEY3 除外）、HDMI IP、SDRAM 仲裁或 FIFO 深度。

这版尚未上板验证。请先检查：上电图片/声音；两页封面与标题；KEY3 来回切至少 20 次（包括播放中/报警中）；KEY2/KEY4 切图；串口音量/亮度/对比度；四向预警；歌词首句、中段、结尾及循环。歌词时间轴由用户歌词和本地 MP3 自动对齐估算，上板试听后可能还需细调；LRC 不用复制进 TF，已编入 B 固件。

若黑屏、花屏、无声或卡顿，请回退双板已验收 R7A/R8B，而非混用新旧 A/B。备份在 accepted_baseline_20261005_r7_r8，未覆盖。源码位于 rtl/dualsong_20261005；回归脚本 sim/dualsong_20261005/run_regression.ps1，重建分别用 prj/dualsong_a_20261005 和 prj/dualsong_b_20261005 的 build_dualsong.tcl。
