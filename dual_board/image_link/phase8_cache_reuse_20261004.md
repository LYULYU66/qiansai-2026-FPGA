# 第八阶段：副板复位后的受保护图片校验复用

本阶段仅改 `dual_board/image_link` 隔离工程，不覆盖单板源码、bit 或此前测试 bit。继续固定分工：B 提供 TF 媒体与计算结果，A 缓存/实际播放/最终显示，并保留本地危险预警。

## 解决的卡点

阶段七握手恢复后，B 从第一张图开始预载；A 若手动停在同一张图，会因禁止重写可见缓冲区而一直不确认，B 无法完成四图预载，PCM 也可能无法重新启动。本轮对**缓存内容未改变**的情况增加只校验、不重写的恢复路径。

正常装载时，A 在接收 CRC16 合法且真正交给 SDRAM 写端的像素流上计算整帧 CRC32。只有完整像素数、协议结束和 SDRAM `write_finish` 均满足，才一起提交缓存有效位、原始尺寸、存储方向与该内容指纹。

恢复时仍沿用 IMG4 / IAK2，不增加包长或第五帧：

1. 若目标缓冲受保护，检查它确实有效，原始尺寸、BMP 存储方向均相同。
2. 用 VERIFY 状态接收整帧 RGB+图层索引，仅计算 CRC32；不发 SDRAM 写请求，也不写一个像素。无论 SDRAM 写端是否 ready，校验都能继续。
3. 中间包仍通过原 stop-and-wait 逐包确认；整帧像素数、协议结束和 CRC32 完全匹配，才确认最后一包。保持有效位、尺寸及提交 toggle 不变。
4. 校验不匹配则保留旧画面、不发最终确认，并复位接收状态。新增 `final_ack_valid` 门控，防止失败的最后一包在重复发送时被旧缓存有效位误确认。

未受保护的图仍正常重新写入和提交；本轮没有仅凭缓存编号/分辨率就跳过加载，也不把 CRC16 合法误当成内容未改变。CRC32 覆盖像素 R、G、B、UI 索引四字节，因此图层改变也会拒绝复用。

## 资源取舍

CRC32 采用反射多项式 `EDB88320`，初始 `FFFFFFFF`；按 R/G/B/索引的字节顺序、每字节 LSB-first 更新，内部保存未最终取反的 CRC 状态。每个像素分成两次 16-bit 更新，显式共用一套运算逻辑，利用原接收器一像素两拍的间隔，不增加正常包的像素排空拍数。四个 32-bit 指纹只需 128-bit 寄存器，无整帧回读或新增大缓存。

| gate 综合资源 | A 阶段七 | A 本轮 | B 阶段七 | B 本轮 |
| --- | ---: | ---: | ---: | ---: |
| LUT / 19600 | 15670（79.95%） | 15935（81.30%） | 13658（69.68%） | 13658（69.68%） |
| 寄存器 | 11307 | 11522 | 10005 | 10005 |
| BRAM9K / BRAM32K | 49 / 7 | 49 / 7 | 27 / 9 | 27 / 9 |
| DSP / PLL | 3 / 4 | 3 / 4 | 3 / 3 | 3 / 3 |

A 净增 265 LUT、215 寄存器，B 不变。两板分别重新综合，保持原 `gate eram_init on`。A 仍需要注意资源余量，不能把 gate 数字当作最终布局资源或时序闭合证明。

CRC32 是低资源的内容指纹，不是逐像素等价证明或安全认证，存在碰撞可能。指纹基于交给写端的流和写完成确认，没有回读 SDRAM 来检测存储位错误。图片内容、图层、尺寸或方向真的改变，且目标仍在显示/转场保护中时，仍安全拒绝；尚未实现自动选择替代缓存更新它。换到其他页面再重载，或重启 A 使缓存失效后正常加载，才允许不同内容写入。

## 测试

固定日志和最终结果以 `phase8_validation_20261004.json` 为准。本轮新增三项：

- `tb_cache_reuse`：真实 IMG4 可靠发送、整包 CRC16 检查、sink、IAK2 收发。逐字节独立 CRC32 参考对照；RGB 或 UI 索引改变；尺寸/方向改变；丢首包及最终 ACK；失败最终包重复发送不假确认；CRC 第二半拍中止；非保护情况下更新内容后，新的指纹仍能复用。
- `tb_cache_reuse_full`：完整 1200 包、307200 个 RGB+索引像素。初次实际写入，改变世代并复位源后同图重发；写端永久不 ready；丢首包与最终 ACK；恢复过程中零 SDRAM 写入。
- `tb_media_restart`：真实 LNK1 双端、两层包仲裁、四缓冲 ingress、AUD2/AAK3、原 512-word PCM FIFO、12.288 MHz 串行器与实际播放头。连续 B 复位五次，分别保护四个缓冲，再保护双帧掩码；每次四图预载均完成，PCM 从新会话第一个样本重启，最终播放头准确到 512。缩短握手时间、用一包代表每个页面，完整尺寸由上一项覆盖。

这三项独立复测于 2026-10-04 20:24:47 完成，全部通过，零 Error/Fatal；联合测试有原 FIFO 未用端口导致的三条警告，未屏蔽。完整回归于 20:37:28 完成，原 27 项与新增三项共 **30 项全部通过**，零 Error/Fatal。完整回归共 64 条警告，仍为原 FIFO 未用端口及历史测试禁用模式下未连接的新端口，没有屏蔽警告。固定日志为 `sim/phase8_modelsim_20261004.log` 和 `sim/phase8_reuse_20261004.log`。

这里替代的是已解码媒体源和 SDRAM 写完成反馈，**没有**测试真实 TF/FAT/缩放→加密 MAC/PHY→SDRAM 存储体→HDMI 屏幕。上一轮保护握手测试和本轮媒体恢复测试组合提供组件级证据，不代表已通过双板硬件联调。

复跑：`& ./dual_board/image_link/sim/run_modelsim.ps1 -Suite Reuse`；完整回归不加 `-Suite`。波形在 `sim/cache_reuse_guard.wlf`、`cache_reuse_full.wlf`、`media_restart.wlf`。最终快照用 `node dual_board/image_link/sim/snapshot_reuse_validation.js`，不覆盖阶段七固定记录。

## 交付边界

未生成正式双板播放器 bit，未做本阶段布局布线或网线/屏幕实测。下一步应审查/补齐正式 A/B 引脚及完整时序约束，再布局布线和生成各自 bit；有网线后验证真实媒体链路与独立复位。

本轮只读检查已确认：A 的 `.al` 仍引用单板 `pin.adc/timing.sdc`，缺少正式 A 网口引脚/输入时钟，且旧视频 PLL 路径和 UART 端口约束需要按实际顶层清理；B 的 `board_b.adc` 有网口/UART/LED，但尚无 `SD_nCS/SD_DCLK/SD_MOSI/SD_MISO` 四个 TF 端口绑定。`constraints/board_a.adc` 属于早期网口测试的端口命名，也不能直接替换正式 A 约束。下一轮应在隔离目录新建匹配正式顶层的约束，不能直接修改单板约束文件或让缺失引脚由工具任意分配。

`backup_phase7_reuse/` 保存改动前双板 RTL、约束、工程清单及阶段七 gate 报告，只是源码快照，不是独立可烧录工程。单板回退 `best_result/lab_ex5_i2s_v1.0_logic_round3_20261003.bit` 和单板顶层 SHA256 均与阶段七相同。
