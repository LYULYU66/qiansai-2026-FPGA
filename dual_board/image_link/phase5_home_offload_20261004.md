# 第五阶段：首页/音乐卡片透明图层迁移

2026-10-04。本轮修改仅在 `dual_board/image_link/`，原单板源码、字模、图片、IP 和可回退 bit 不改动。正式播放器仍未完成布局布线或发布新 bit；不能把行为仿真和 gate 综合当作上板成功。

## 分工与保留行为

副板 B 保存、展开首页和第二页音乐卡片的无损压缩静态图层。主板 A 不再计算这些卡片的几何、字体和图标地址，只通过一个小调色板叠加。统一实时 HH:MM 时钟、歌词/频谱绘制、本地拨码预警和音频报警仍在 A；音频分析、歌词进度仍由上一阶段的 B 计算。

没有把卡片烘焙进 BMP 的 RGB：每个原 32-bit SDRAM 像素字的高 24 位仍是原图，原本置零的低 8 位变为图层颜色索引。因此仍用原四个帧缓存、原地址、原 SDRAM 接口和 FIFO 深度，不新增整帧存储。

- 索引 0 透明，保留原图；1–151 对应原图层的 151 种不透明 RGB 色。
- 图片亮度/对比度仍只处理高 24 位，调色板在其后输出；白卡片、图标、字体不随图片调节变灰。
- 转场及预警切页沿用原使能逻辑，图层可独立隐藏；没有对索引做 Alpha 插值，也不会让卡片跟着图片转场。
- 第一页四张白色圆角卡片、底部矩形导航栏、圆形导航图标、应用图标、胎压示意和日期/太阳保留。
- 第二页音乐卡片保留；实时歌词、滚动字幕、频谱/波形、左右 VU 和统一时间通路不删。
- 第三/四页索引恒 0，休闲星点和方向预警通路不变。

## 为什么采用这个方案

先用 ModelSim 导出未修改的 `video_home_overlay`（EXTERNAL_CLOCK=1）两页 640×480 图层，背景设为一个未被图层使用的标记色。普通逐行 RLE 仍需过多 A 的 BRAM9K，故没有在 A 存整个透明图层。

去重相同扫描行后，图层是 **216 个不同扫描行、13860 个 16-bit RLE 字、152 个含透明项的颜色**。B 用 **7 BRAM32K** 存 RLE，**2 BRAM9K** 存 1024 项行地址表；A 用 **2 BRAM9K** 存小调色板。B 每个被网络发送器接受的源像素才推进一次索引，TF 停顿、网络背压、同包重传均不推进图标位置。

BMP bottom-up 用 y=479→0 查行，top-down 用 y=0→479；RGB 和索引一起写入现有 SDRAM 写通路，由同一个行方向翻转，避免图标倒置。逐像素展开与原图层色值一致，没有重采样、降低图标分辨率或再次量化颜色。

资产可重复生成：先执行 `sim/run_modelsim.ps1 -Suite HomeCapture`，再执行 `node sim/generate_home_atlas.js`（从对应目录使用正确相对路径）。生成物在 `rtl/home_assets/`，无需向 TF 卡添加图标文件。静态图层来自现有 UI 的离线确定性编译，副板运行时负责展开，**不是通过网口动态发送整屏 HDMI 视频**。日后改卡片布局/静态文字需重新生成资产并更新两板程序；目前胎压仍是原固定演示值，不是真实传感器读数。

## IMG3 协议

原 IMGF/IMG2 默认组件模式继续保留供历史测试。正式媒体 A/B 同时开启 UI_TAG=1，使用新的 IMG3；不能把本轮的一块板和旧 IMG2 播放器混搭。

| 字节 | 内容 |
| --- | --- |
| 0–3 | ASCII `IMG3` |
| 4 | 帧缓存号 0–3 |
| 5–6 | 包序号 u16，小端，0–1199 |
| 7 | bit0 为 BMP top-down，其余为 0 |
| 8–11 | 加载会话 token u32，小端 |
| 12–1035 | 256 个像素，每像素 R、G、B、图层索引 |
| 1036–1037 | CRC16/CCITT-FALSE，大端，覆盖字节 0–1035 |

每包 UDP 应用载荷 1038 字节，仍在普通 1500 字节 IP MTU 内。IAK2 确认包及可靠重传、重复包不重复写入、非显示缓冲保护、写完才提交逻辑不变。图片载荷比 RGB888 多 **1/3**，每帧新增 307200 字节；四帧只在首次加载/重新加载时发送，不按每次刷新发送。图片传输变长是迁出主板绘图逻辑的代价，PCM 仍在包边界有优先权。

## 资源：gate 综合，不是布局布线

| 指标 | A 第四阶段 | A 本轮 | B 第四阶段 | B 本轮 |
| --- | ---: | ---: | ---: | ---: |
| LUT / 19600 | 16700 / 85.20% | 14919 / 76.12% | 12082 / 61.64% | 12227 / 62.38% |
| 寄存器 | 10441 | 10442 | 9285 | 9347 |
| BRAM9K / 64 | 57 | 49 | 25 | 27 |
| BRAM32K / 16 | 7 | 7 | 2 | 9 |
| DSP / 29 | 3 | 3 | 3 | 3 |
| PLL / 4 | 4 | 4 | 3 | 3 |

本轮 A 净省 **1781 LUT、8 BRAM9K**；B 增加 145 LUT、2 BRAM9K、7 BRAM32K。A 的首页叠加层级由原约 1571 LUT / 10 BRAM，变为 2 LUT / 2 BRAM；整体净差还包含包宽度及综合映射变化，不能把层级差简单当成全局差。

两板明确启用 `gate eram_init on`，RLE 使用原生 EG_PHY_BRAM32K 的 INIT 参数；调色板和行表也有初始化数据。仍保留原加密网口、SDRAM/IP 的既有综合警告，需要正式约束、布局布线和硬件阶段审查，不宣称零警告或时序闭合。

## 验证范围

新增行为/接口测试：

1. `tb_home_atlas`：副板原生 BRAM32K 模型、全页无损索引、两种 BMP 行方向、四个页面、背压、复位重开。
2. `tb_home_pixels`：1228800 个像素逐个对照未修改的原首页/音乐卡片模块，包含变化背景和图层使能。
3. `tb_image_tagged_full`：1200 包/307200 RGB+索引像素；破坏最后一个图层索引字节触发 CRC 重传；首尾 ACK 丢失、写端停顿、完整帧提交，检查索引和 RGB 都不重写/漏写。
4. `tb_home_pipeline`：1843200 像素通过真实 `video_delay`、转场及亮度 LUT，检查图层索引的行首/帧首对齐，四档图片调节以及转场/预警隐藏。
5. `tb_home_source`：实际 B 包装模块的 100/125 MHz 像素 FIFO、索引展开、可靠发送/接收与背压，两张图合计 614400 像素，覆盖 bottom-up/top-down。这里只替代 SD 解码后的像素输出，**不代表完整 TF/FAT 文件系统仿真**。

最终 **18 项整轮回归全部通过**：2026-10-04 16:06:58 开始，16:16:18 完成，ModelSim Starter 10.5b。零 Error/Fatal，24 条警告：12 条来自原 FIFO 未使用端口，12 条来自旧 UI_TAG=0 测试未连接的新索引端口（该模式不使用索引）。没有屏蔽警告，也未修改原 FIFO/IP。

上一阶段 13 项已整轮重跑；其中三流复用的 `tb_audio_offload` 更新为实际 IMG3 包长度，并逐像素检查图层索引，保留 PCM/增益、断流恢复与分析器对照检查。完整命令在工程根目录：`& ./dual_board/image_link/sim/run_modelsim.ps1`；只重跑本轮用 `-Suite Home`。最终结果及源码/日志哈希由 `phase5_validation_20261004.json` 记录。

日志是 `sim/modelsim_regression.log`，五项新波形分别是 `home_atlas.wlf`、`home_pixels.wlf`、`image_tagged.wlf`、`home_pipeline.wlf`、`home_source.wlf`。首轮像素导出曾因未编译原封面/应用 ROM 而展开失败，补齐依赖后成功；本次完整回归没有沿用失败日志作为通过证据。

不覆盖真实 PHY/网线、加密 UDP/MAC 的内部行为、SDRAM 存储体或 HDMI 屏幕；无网线时不能替代上板检查。视频链路测试检查的是定义的栅格索引与当前像素的对齐，未声称实机零闪烁。
