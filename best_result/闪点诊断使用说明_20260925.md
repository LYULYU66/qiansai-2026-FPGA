# 静止底图零星闪点：可切换诊断版

诊断固件：`best_result/lab_ex5_i2s_v1.0_pixel_diag_20260925.bit`。原默认文件 `best_result/lab_ex5_i2s_v1.0.bit` 仍然是旧版，不能用它测试新增命令。

## 目的与边界

用户已确认：烧回 `vehicle_hazard_vu.bit` 后，静止图片上半部分仍轻微闪动，框外底图闪、状态框正常。本版用于收集证据，不宣称已经修复闪点。

本版恢复原 SOF 判定（撤回最近的 SOF 边界修改），保留已有播放、音频、字幕、亮度/对比度、预警功能。没有修改 SDRAM 仲裁、FIFO 深度、读延迟、PLL 或 HDMI PHY。只增加像素源选择和只读标志。重新构建会重新布局，因此不是旧 bit 的逐位复制；需要先在本版 TEST 0 中确认原现象能否复现。

三种模式共用同一个 bit，切换时后台 SD、SDRAM 和音频继续运行，避免更换不同编译版本或停止后台引擎造成更大的对照差异。像素切换只在 VS 上升沿的消隐期提交。原默认 bit 和旧版回退文件不覆盖。

## 操作

串口采用 **文本/ASCII，115200、8-N-1**，每条命令以回车或换行结束。等待上一条回复后再发下一条。

1. 烧录本轮单独生成的诊断 bit。上电默认 `TEST 0`（正常画面）。停留在会闪的那张暗图，不轮播；三个危险模拟开关关闭。
2. 发送 `BRI 100` 和 `CON 25`，保证测试图没有因亮度/对比度设置而变成全黑。
3. 在每个模式下都执行：`TEST n` → 等待约 1 秒 → `DCLEAR` → 观察 10 秒 → `DIAG`。保存三组现象和回复。
4. 测试结束发送 `TEST 0` 恢复完整画面，或重新上电。

| 命令 | 输出画面 | 含义 |
| --- | --- | --- |
| `TEST 0` | 原图片和原叠加层 | 确认闪点在这个诊断 bit 上是否仍能复现 |
| `TEST 1` | 固定暗灰竖条和原叠加层 | 用本地像素代替缓存图片，仍经过亮度/对比度与全部叠加模块 |
| `TEST 2` | 只有固定暗灰竖条 | 本地像素绕过图像调整和叠加层，送入同一个 RGB→AXIS 适配器与 HDMI 核 |

暗灰竖条每 16 像素改变一次灰度，0/8/16/24/32/40/48/56 周期重复，上下半屏内容相同，正常情况下完全静止。TEST 2 临时隐藏包括预警边框在内的所有图层，只用于桌面调试，声音与后台功能仍运行。

`TEST n` 回复 `OK TEST=n`，代表命令接受，不代表下一帧已提交。`DIAG` 的 T 才是实际提交的模式。`TEST 3` 或其他无效值回复 ERR，设置不变。

`DCLEAR` 回复当前请求模式 `OK TEST=n`，不切换模式，只清除记录；跨时钟传播需要若干拍，随后出现的新事件会再次置位。

## DIAG 回复

示例：`T=0 A=0 B=0 H=0`

- T：视频域当前实际模式。
- A：清除后，显示有效期间，主读 FIFO 曾发生 `read_en && empty`。
- B：同上，但针对转场第二路 FIFO；仅在第二路开启时记录。
- H：显示有效且 HDMI 核报告锁定时，曾发生 `valid && !ready`。这是握手暂停事件，并不单独证明它一定引起可见闪点。

三个标志均为粘滞标志：短暂事件也保留为 1，直到 DCLEAR 或复位。查询不会自动清除。初始化阶段及更换模式后的既有记录应先用 DCLEAR 排除。H 不监测锁定前的暂停，也不代表锁定状态检测；A/B 不检测非空 FIFO 中的数据位错误。

## 如何解读

- TEST 0 有闪点、TEST 1/2 均稳定：把后续检查重点放回图片读出、转场数据和相关路径；不能据此绝对排除图案相关的输出问题。
- TEST 1 有闪点、TEST 2 稳定：进一步隔离亮度/对比度和叠加路径。
- TEST 2 仍闪：不能再把现象仅归因于 TF 图片读出；继续检查共同使用的时序、发送接口、物理连接与显示端。
- A/B 为 1：已抓到实际空读，结合发生模式、静止/切换时机定位供数问题，不能只凭标志决定加大 FIFO。
- H 为 1：已抓到 ready 暂停，应核实发送核接口要求和是否丢像素，不能直接改 HDMI PHY。
- 全为 0：仅说明没有捕获到上述三类事件，不代表整个链路无错；本版不包含 CRC 或逐帧像素比较。
- 若 TEST 0 不再复现：本轮重布局改变了条件，不能把测试图稳定当成根因已排除，请同时报告这一点。
