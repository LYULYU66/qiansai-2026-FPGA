# 高分辨率 BMP 双线性缩小版本（2026-10-02）

交付 bit：`lab_ex5_i2s_v1.0_bmp_bilinear_downscale_20261002.bit`。
以 Claude LUT 优化版 `lab_ex5_i2s_v1.0_lut_opt_20261002.bit` 为基础。原 bit、完整音乐和已有图标/歌词资产保留。

## 功能与范围

- 解析 BMP 信息头中的原始宽度、带符号高度、位深、压缩类型、像素偏移及行填充。
- **只支持原始宽度 ≥640、绝对高度 ≥480 的 24-bit 非压缩 BI_RGB BMP**；640×480 保持原像素，高分辨率通过双线性插值缩小到640×480。
- 低分辨率放大支持已删除；任何一边低于对应输出尺寸的图片都不接受，包括宽图但高度不足480的图片。
- 宽、高各用16位表示，最大65535；实际还受 BMP 文件长度、TF文件系统和装载时间限制，不表示已实测65535×65535图片。
- 支持正高度（自下而上）、负高度（自上而下）、像素偏移跨扇区、行尾填充及碎片化 FAT 链。DIB长度至少40、planes=1。32-bit、压缩 BMP、JPEG/PNG 不支持。
- 填满640×480输出，不做等比例黑边或裁剪。比如1920×1080会压缩到4:3，形状会有一定变化；图片内容和原始分辨率元信息是独立的。
- 左上角原有 BRI / CON / VOL 右边新增 **RES:原始宽x高**，同一套清晰字模、无状态框。随实际显示的图片索引更新，包括预警直接切页。
- 四张图片仍在上电时预装到原有 SDRAM 帧缓存；之后轮播、转场、串口调节、预警、音频可视化和歌词通路保持。TF卡文件数量、图片命名约定和 MUSIC.PCM 格式均不用改。
- 缩放在**装载时**执行，不在 HDMI 逐帧输出时重复计算。高分辨率文件读得更久；音乐原本在四张图预装后开始，因此上电等待也可能延长。HDMI输出仍为640×480。

## 节约资源的实现

两个目标行宽的 RGB Q8 行缓存（每行640×3×16位，分别占一个BRAM32K）；1024字节的输入信用FIFO（一个BRAM9K）；一个有符号乘法器分时处理RGB及横/纵插值（一个DSP）。没有新建整幅高分辨率片上帧缓存，也没有单独的放大通路。

串行除法在每张图开始时计算坐标步长，商/余数DDA避免逐点除法及步长截断累积误差。横向保留8位小数，纵向完成后统一四舍五入。读TF前预留一整个512字节扇区的空间，输出按既有写FIFO余量暂停，避免输入/输出突发时丢字节或像素。原有FIFO深度未增加。

分辨率转十进制使用时分BCD转换，不使用组合除10；RES所需 E/S/x 字形放进原有状态字库的空槽，不增加字库BRAM。

## 时序限制（必须注意）

本版 **尚未时序收敛，也未烧板验证**。

- 全局建立WNS **−5.699 ns**（与原版相同的SDRAM接口IO路径类别）；TNS −243.261 ns。
- 全局保持WNS **−1.519 ns**；TNS −9.293 ns。原版是−1.141 ns，本版更差。
- SD 100MHz建立WNS **−0.757 ns**，原版−0.072 ns，本版仍更差，不能说本功能对时序没有影响。
- 视频25MHz建立WNS **+2.441 ns**；视频保持−0.044 ns。
- 板载50MHz时钟保持WNS **−0.932 ns**；相关原始路径请查完整报告。
- 种子7也完成布线，LUT16931、SD建立−2.141 ns、视频建立+1.635 ns、全局保持−1.240 ns；种子19优先改善SD与视频建立时间，但保持更差。种子3有一个局部布线冲突，没有生成可交付bit。

没有改PLL、引脚、HDMI核、SDRAM仲裁、FIFO深度，也没有新增假路径来掩盖负裕量。因此此bit是**待上板验证版本**，不能保证板上全部稳定。

## 复现与上板检查

完整回归（原42项+新缩放及集成测试）：

```powershell
.\sim\run_bmp_downscale_20261002.ps1
```

只重跑较快的集成/等价部分（不表示重跑了全部回归）：

```powershell
.\sim\run_bmp_downscale_20261002.ps1 -IntegrationOnly
```

重新构建选定版：

```powershell
.\sim\build_lut_opt_20261002.ps1 -SynthesisRun syn_bmp_downscale_20261002 -PhysicalRun phy_bmp_downscale_s19_20261002
```

上板先用原有四张640×480图片检查图片顺序、切换、音频、串口、歌词及四方向预警；再替换其中一张为1280×720或1920×1080的24-bit非压缩BMP，核对RES、画面方向、四角内容、轮播及音频。所有四张图片均应满足宽≥640且高≥480。

如有异常，恢复 `lab_ex5_i2s_v1.0_lut_opt_20261002.bit`（原始备份不支持新缩放，需要继续使用640×480图片）。没有自动烧录板卡，也没有修改TF卡文件。
