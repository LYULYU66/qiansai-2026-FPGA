# 第一轮低风险低功耗优化（2026-10-02）

本轮以用户确认上板正常的 clock_startup_fix 版本为基线，保留全部功能。新 bit 尚未上板验证。目标是减少不可见页面的无效活动，不承诺本轮降低 LUT，也未测量整板瓦数。

## 交付与回退

新 bit：[lab_ex5_i2s_v1.0_low_power_round1_20261002.bit](lab_ex5_i2s_v1.0_low_power_round1_20261002.bit)

回退：[lab_ex5_i2s_v1.0_clock_startup_fix_20261002.bit](lab_ex5_i2s_v1.0_clock_startup_fix_20261002.bit)

TF 卡图片、MUSIC.PCM、串口命令及接线均不用改变。回退 bit 的 SHA256 已重新核对，未改动。

## 本轮改动

1. 首页、预警页没有可视化消费者时，暂停波形/频谱分析；音乐页继续分析，休闲页也继续分析，保留星点的 VU/频谱驱动。转场按照原显示使能决定是否分析。
2. 休闲页隐藏时，暂停星点位置和行缓存更新，并冻结星点状态；重新进入时恢复运动、重建行缓存。坐标同步仍运行，不增加视频延迟。波形与 VU 尚共用一个分析器，本轮没有进一步拆分。
3. 歌词当前句/下一句没有改变时，不再每帧重载字符。逐字红色进度、句间滑动、音乐时间轴保持更新；进入页面及歌曲循环后会刷新必要字符。
4. 时钟字模只在实际数字绘制区域读出；频谱历史 RAM 只在处理音频样本所需的周期读取。

没有更改 PCM 输出、报警混音、歌词采样时基、SD 读取/高分辨率缩放、SDRAM、FIFO 深度、PLL、HDMI 核、引脚或时序约束。80 个生产源码/IP/约束文件中 74 个 SHA256 与基线一致，另外 6 个修改前源码已备份在 backup_before_low_power_round1_20261002/。

采用寄存器/存储器使能，不用组合逻辑门控时钟，不改变电压。全局时钟树仍运行；RAM 读请求减少不等于同等比例的 RAM 功耗或整板功耗下降。

## 时序与候选选择

使用同一份综合结果比较 4 个布局种子：3、7 完成布线；11 有局部布线冲突，19 的 MSlice 打包超限，失败候选均未交付。选用种子 3，原因是视频建立/保持均为正，且 SD 建立裕量优于当前上板正常旧版。

| 时钟 | 正常旧版建立/保持(ns) | 本轮建立/保持(ns) |
|---|---:|---:|
| 视频 25 MHz | +2.604 / +0.004 | +1.632 / +0.003 |
| SD 100 MHz | −1.771 / −0.012 | −1.638 / −0.020 |
| SDRAM 100 MHz | −5.699 / −1.203 | −5.699 / −1.222 |
| 系统 50 MHz | +5.029 / −1.170 | +4.483 / −0.525 |
| 音频 12.295 MHz | +64.910 / +0.132 | +63.630 / +0.110 |
| HDMI 125 MHz | +0.195 / +0.330 | +0.393 / +0.320 |

全局建立 −5.699 ns、保持 −1.222 ns。时序尚未闭合，不能保证全部温度、电压和板卡条件下可靠。视频裕量比旧版略小，SD/SDRAM 保持裕量也并非全部改善，因此新版本仍需上板验证，不能把“通过仿真”当成“板上完全可靠”。

## 上板检查顺序

1. 冷启动数次，确认四张图、音乐启动和数码管均正常。
2. 停留首页/预警页 30 秒，音乐不能停止；返回音乐页，确认歌词仍与当前歌曲位置同步，频谱和波形恢复。
3. 离开休闲页后再次进入，确认星点恢复、时钟继续走，不花屏。
4. 开关四方向预警，确认立即跳转、红框、音乐减弱及报警声；解除后继续切图。
5. 检查 UART 音量、亮度、对比度和显示命令；至少播放一次整曲，检查歌词前奏与循环。

若出现异常，先烧回已确认正常的 clock_startup_fix bit，并说明异常发生在哪一页、是否影响音乐。待此轮板上确认后再进行资源压缩轮。
